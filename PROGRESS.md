# Detached Signatures Implementation Progress

## Current status

Automerge verifies Ed25519 records itself, synchronously; signing stays outside, since private keys often live in Web Crypto or hardware. Authentication is decided per chunk, where a chunk is one unit of transport — a change chunk, a bundle chunk, or a whole document. A chunk declares the signatures it needs, is held whole until they verify, and is then accepted whole. Because the fragment index holds the minimal covering set of fragments, and a chunk is only ever accepted fully covered, the export invariant holds by construction: anything the document can export already has the signatures it needs.

An encoded chunk stream already carries those boundaries, so the ordinary incremental load is the import path: each change chunk in it is a level-0 commit needing its own signature, each bundle chunk needs signatures for every actor maximum it contains, and the signatures must accompany the history they authenticate. What is refused is handing over loose `Change` values with no stream to read boundaries or signatures from — `apply_changes`, `merge` — and the sync protocol, whose messages carry neither.

The mode is fixed when a document is created and inherited by a fork, so there is no window in which a document accepted history under one rule and then claimed the other.

## Design note: why per chunk

An earlier iteration authenticated per change: it staged loose changes, tracked a per-actor authenticated frontier, walked actor chains backwards to prove they were contiguous and hash-linked to sequence one, and then selected the largest dependency-closed subset of staged changes to apply. Deciding per chunk removes all of that. Gone are the per-actor frontier state, the accepted-plus-staged dependency walks, the backwards chain grounding, the batch-selection loop, the staging actor/author indexes, and the frontier invalidation needed when a local edit replaced a staged branch.

What replaces it is one check at decode time, confined to the chunk: every change must be in the causal history of its own actor's maximum within that chunk. That check is what makes one signature per actor sound, since a signature's target hash commits to its own causal history and nothing else. It is also exact rather than approximate, because a fragment's members are causally closed on `(boundary, head]`.

## Technical notes

- Importing a chunk stream validates every chunk before the document changes, so no clone is needed to keep a bad stream from leaving history behind. A small import into a large document costs what the legacy path costs, plus one remembered Ed25519 verification per actor maximum.
- `add_signatures` constrains nothing about what a record targets. It is in practice fed from `signing_requests`, which reports this document's own unsigned commits, but a record only ever authenticates by verifying under the author of its own change, so admitting one for anything else cannot make visible what a signature from that author would not have. Records for history the document does not hold are retained and relayed, as they are when they arrive in a chunk stream.
- Paths which replay history before knowing what is authenticated — `fork_at`, and loading a document chunk — rebuild the fragment index afterwards. Without that a trusted-snapshot load or a fork at heads offered an unsigned commit's fragment as exportable, which `bundle_fragments` then refused, so the signed history it had absorbed became unexportable by a second route.
- Every fragment the document offers is exportable, by construction rather than by filtering: formation is deferred until the history is authenticated, and enumeration starts from the authenticated frontier. This also fixes a real defect — a change whose hash begins with a zero byte forms a higher-level fragment, so an unsigned local commit forming one absorbed the signed history beneath it into something unexportable. One commit in 256 has such a hash, so a single unsigned commit could make an entire document unexportable; measured at commit 495 of a 2000-commit run, where it hid all 495 signed changes.

- The `fragment_export_blockers` diagnostic from the earlier opaque design is gone. `signing_requests` names everything that can be signed and is not, and the only other reason a fragment is withheld is an actor whose author is not a usable Ed25519 key, which no API could make actionable.

- Verification is synchronous, so a whole-document chunk is authenticated like any other: the records in the same stream must cover every actor's greatest sequence, and an uncovered chunk is refused rather than held, because a document carries its own authors. `own_storage` narrows that for an application's own bytes, admitting unsigned history under the author the load declares, which is the only way an unsigned local draft survives a restart. It is an assertion about provenance, not a property of the bytes: an author is a public key any chain can claim.
- A verified target is remembered, because the key it is checked against is fixed by the change itself. That memory is never serialized.

- `ChangeQueue` remains the queue for already accepted changes waiting on missing dependencies. `PendingChunks` is separate so unverified input cannot be mistaken for accepted CRDT state. A pending chunk stores only its changes and the hashes it requires: causal readiness stays the queue's job, and the queue only sees changes that have crossed the authentication boundary.
- Requirements are keyed by change hash, never by sequence number, which is what stops a signature over one branch from being made to cover an alternate change at the same sequence. The frontier invalidation the per-change design needed is therefore unnecessary.
- A chunk that cannot be authenticated by construction is rejected at import rather than held: an actor claiming one sequence twice, a change outside its own actor's maximum's history, or a stream carrying more than one fragment.
- Local unsigned changes remain immediately visible in authenticated mode.
- Authenticated fragment enumeration/export requires a verified Ed25519 record at each canonical fragment actor maximum. An actor with no author, or an author which is not a usable verifying key, can never be signed, so `signing_requests` does not report it and its fragments stay withheld.
- Switching an existing document into authenticated mode arms gating from that point on. It does not retroactively audit history already accepted in legacy mode, which is the trusted local baseline.
- `VerificationStatus` has `Unverified`, `Valid`, and `Invalid`; contradictory final-result transitions are rejected. JavaScript submits results as one atomically validated reconciliation batch. Verification request inspection is repeatable, and callers own in-flight tracking and deduplication.
- JavaScript commit and fragment `bytes` contain the unchanged primary chunk followed by a detached signature chunk. This preserves `ChangeHash` while allowing opaque relays and ordinary ingestion APIs to handle one byte string.
- Sync and proof export for arbitrary historical changes are explicitly deferred by `SIGNATURES.md` and are not part of the initial milestone. Sync would need a chunk boundary of its own before it could participate.
